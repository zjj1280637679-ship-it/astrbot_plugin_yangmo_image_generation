# 视频生成

这是 AstrBot 原生 Skill。遵循渐进披露：命中视频任务后才读取本文件。视频 Tool 始终可直接调用；Skill 负责帮助主 Agent 组织高质量视频意图，而不是建立固定状态机。

## 核心能力

视频后端采用两路轮换：Seedance 为主路线，CogVideoX-Flash 为可选轮换路线。默认开启声音。

当前插件稳定暴露：

- 文生视频；
- 单首帧图生视频；
- 5 秒 / 10 秒；
- `adaptive`、`1:1`、`16:9`、`4:3`、`21:9`、`9:16`、`3:4`；
- 480p / 720p / 1080p；
- 默认生成与画面同步的声音；
- Seedance 有声路径默认使用 `doubao-seedance-1-5-pro-251215`；
- Seedance 创建任务前遇到明确的限流、额度、过载或服务端错误时，可轮换到 `cogvideox-flash`；
- Seedance 可请求返回生成视频尾帧并保存为 `genframe:`；
- 生成视频保存为 `genvideo:`，默认直接发送到当前聊天。

首尾帧同时约束在不同资料中存在口径差异，因此当前不把它作为稳定 Tool 参数暴露。不要伪造不存在的能力。

## Harness 语义

`generate_video` 默认：

1. 立即发送一条简短开始通知；
2. 根据当前配置选择 Seedance；必要时才轮换 CogVideoX-Flash；
3. 程序轮询异步任务；
4. 成功后下载 MP4 到插件私有存储；
5. 默认自动发送视频；
6. 返回 `genvideo:`、可选 `genframe:`、任务信息和一张内部预览给当前 Agent。

Agent 可以自由关闭机械默认：

- `announce=false`：已经自己预告，或用户要求纯结果；
- `auto_send=false`：先做候选、内部比较、继续迭代，最后只交付选中的视频。

不要建立 `prepare`、句柄或固定前后话术。

## 首帧来源

`first_frame` 支持：

- 空字符串：文生视频；
- `current`：当前用户消息中的第一张图片；
- `genimg:...`：本插件图片生成物；
- `genframe:...`：本插件上一次视频返回的尾帧；
- `resolved`：本轮最近一个其他 Tool 返回的 ImageContent。

`resolved` 是松耦合互操作入口。典型场景：群聊图片定位/搜索插件先把原图作为工具图片交给 Agent，然后调用 `generate_video(first_frame="resolved")`。本插件不导入其他插件，也不读取其他插件数据库或提取码存储。

如果上下文里只有 `ctximg:` 等其他插件私有提取码，先调用对应公开解析工具，再使用 `resolved`。不要把别的插件提取码直接塞给视频 API。

## 提示词方法

视频提示词重点描述**变化 + 声音**，而不是只重复首帧静态内容。优先组织：

`主体状态 → 动作变化 → 环境响应 → 镜头运动 → 时间顺序 → 光影/风格 → 声音设计 → 连续性约束`

### 声音描述默认存在

除非用户明确要求静音/无声，视频提示词应带一段简洁但具体的声音设计。不要只写“有声音”，而要根据画面描述：

- 环境声：风、雨、人群、室内混响、机械噪声、城市底噪等；
- 动作音效：脚步、衣料、撞击、羽翼、车辆、武器、物体移动等；
- 人声：只有场景确实需要对白、口播、喊声或呼吸时才写，并说明语气/距离/情绪；
- 配乐：只有用户或场景需要时才写风格、节奏和进入/退出时机，不要让 BGM 盖过主体声音；
- 同步关系：声音变化尽量和时间段、动作节点、镜头切换对应。

推荐在提示词里直接使用类似：

`声音：远处低沉雷声和连续雨声；人物抬头时衣料摩擦与呼吸声更清楚；汽车掠过时轮胎压水声从左向右扫过；不加旁白，背景音乐极弱。`

如果 Agent 没有写任何声音描述，插件会补一条通用的同步环境声/动作声说明作为安全兜底；但 Agent 能根据上下文写出具体声音时，应优先由 Agent 自己描述。

Seedance 路线默认开启原生音频生成；若基础 `video_model` 是不支持有声生成的旧模型，插件会自动使用配置中的有声 Seedance 模型。CogVideoX-Flash 路线默认发送 `with_audio=true`。

文生视频示例思路：

“雨夜街口，一个男人先低头站立，0-2 秒缓慢抬头看向远处；2-4 秒镜头从中近景稳定推进，背景汽车灯光扫过湿地；最后 1 秒人物停住，表情紧张。声音：连续雨声铺底，人物抬头时可听到近距离呼吸和衣料摩擦，汽车经过时有短促的轮胎压水声由远及近再远去；无旁白。冷色电影摄影，自然运动模糊，人物身份和服装保持一致。”

首帧图生视频时，不要浪费大量文字重新描述已经可见的画面。优先写：

- 哪些身份/服装/构图必须保持；
- 从首帧开始发生什么；
- 动作的先后顺序；
- 运镜方向和速度；
- 与动作同步的声音；
- 不希望突然新增/消失/变形的元素。

例如：

“保持首帧人物身份、服装、翅膀结构和背景连续。人物先缓慢抬头，随后展开双翼；羽毛受气流轻微抖动，衣摆自然摆动。镜头由中景缓慢后移，最后人物离地上升。声音：展开翅膀时出现层次清晰的羽毛摩擦与强风声，离地后风声增强，背景保持低沉空间环境声；无旁白。不要新增人物，不要突然换景，不改变面部与服装设计。”

## Agent 自适应

- “越快越好”：减少额外规划，直接生成；通常保持 `announce=true`、`auto_send=true`，声音只写最必要的同步描述。
- “先做三版，选最好”：第一次可预告；候选使用 `announce=false, auto_send=false`，由 Agent 根据预览和任务预算决定是否继续。
- “先别发”：使用 `auto_send=false`。
- “生成后锐评”：交付不会终止 Agent loop；利用返回预览继续评价即可。
- “接着上一段”：优先使用上次返回的 `genframe:` 作为新首帧，减少段落衔接跳变；声音风格也应延续上一段。

视频生成是高成本、长等待动作。只在任务确实需要生成视频时调用；不要为了讨论、规划或解释视频而发起真实 API 请求。
